# ADR-0007: Mandatory Multi-Stage Evidence Redaction Pipeline

> **Status:** APPROVED  
> **Date:** 2026-09-22  
> **Deciders:** Lead Product Architect, Lead Security Engineer  

---

## 1. Context
Web vulnerability scanners record HTTP requests and responses as proof of detected vulnerabilities. If raw responses are saved directly to the database, Zerivex risks becoming a high-value target containing captured session cookies, bearer tokens, API keys, basic authentication credentials, and customer personal data.

## 2. Decision
All evidence generated by scanner check modules must pass through a strict, synchronous multi-stage redaction pipeline before reaching the persistence layer:

```
Raw Response
     ↓
Evidence Extraction (Extract only relevant lines/headers)
     ↓
Sensitive Header Redaction (Authorization, Cookie, Set-Cookie, Proxy-Authorization)
     ↓
Secret Token Masking (Regex scrubbing for Bearer, JWTs, API keys, private keys)
     ↓
Size Limit Enforcement (Cap snippet at 64KB per finding)
     ↓
Safe Redacted Evidence
     ↓
Database Persistence
```

1. **Explicit Masking:** Redacted secrets are replaced with `[REDACTED_BY_ZERIVEX]` indicators to preserve finding clarity while eliminating secret exposure.
2. **Access Control:** Evidence is strictly tenant-scoped and accessible only to authorized members of the organization owning the scan.

## 3. Consequences
- **Positive:** Protects customer credentials from data exfiltration and database disclosure attacks.
- **Negative:** Slightly increases processing latency during evidence recording (minimal, sub-millisecond).
